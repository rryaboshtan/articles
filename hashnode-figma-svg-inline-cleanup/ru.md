# SVG из Figma в файле ок, в inline ломается

Клип фрейма сняли. Шеврон в вкладке виден. Кидаешь две иконки в React — одна пропадает, градиент течёт, SVGO «оптимизирует» линейную иконку в чёрную заливку. В тикете виноват фреймворк. Документы просто не писали так, чтобы они делили одну страницу.

SVG, открытый как файл или через `<img src>`, — **отдельный документ**. Его `id="clip0_12_8"` живёт там. Инлайн в HTML или JSX — все иконки делят пространство имён id и CSS страницы. Экспортёр Figma не знает, что ты вставишь сорок таких рядом. SVGO не знает, что `clip0_12_8` был фреймом. Модель stroke на канве богаче SVG, поэтому «в Figma нормально» всё равно везёт аппроксимацию.

**Коротко:** если ломается только в inline — сначала дубли id и `.st0`, не React. Префиксируй или сними id. Удали редакторский `<title>` и общие таблицы стилей. Не гоняй дефолтный пресет SVGO по файлу, на который не смотрел. Outline текста и выравнивание stroke решай **в Figma** на весь набор. Если превью пустое или съехавшее *уже как один файл* — это не эта статья, вернись к [инспекции графа сцены](https://getsvgeditor.com/blog/ru/figma-svg-empty-shifted-clipped).

Здесь проход в прод: столкновения, хвосты машинерии, обводки, булевы, фильтры и рецепт, который масштабируется дальше одной героической чистки.

## Страница — одно пространство имён id

Те же два файла **инлайн** в HTML или JSX делят пространство имён id страницы и CSS страницы. Второй `clip-path="url(#clip0_12_8)"` указывает на `clipPath` первой иконки. В зависимости от порядка один глиф пропадает, оба кропаются не тем прямоугольником, или градиент иконки A заливает иконку B. Классы `.st0` / `.st1` из таблиц в духе Illustrator перекрашивают то, что совпало последним.

Поэтому «у дизайнера в превью всё ок» и «React-компонент пустой» могут быть оба правдой. Превью было одним документом. Приложение — куча документов.

`url(#clip0_12_8)` — **документный** фрагмент (`getElementById`), не скоуп `<svg>`. В дереве побеждает первый id. Вложенный `<svg>` скоупа не даёт; shadow root или `<img>` — да. Не «чини» обёрткой `<svg>`, пока не изолируешь (shadow у custom element или оставь `<img>`).

**Что делать:** без id, пока краска/клип не настоящие — иначе префикс (`icon-chevron-grad`, не `paint0_linear_12_8`). SVGO `prefixIds` в CI. Разово: переименуй до второй иконки.

## id, title и стили, которые взрываются позже

**Паттерн id у Figma.** `clip0_12_8`, `paint0_linear_12_8`, `filter0_d_12_8` — числа из id нод файла. Они стабильны для этой ноды и **не уникальны между файлами**. Два файла Figma могут выдать один и тот же `clip0_1_2`. Считай каждый экспорт сталкивающимся, пока не префиксировал.

**`<title>Layer 1</title>` / `Frame 214` / имя компонента.** Скринридер может это произнести, когда SVG инлайн и не `aria-hidden`. У UI-иконки глиф — `aria-hidden="true"` (и `focusable="false"` по привычке старых IE/Edge) на `<svg>`, доступное имя — у **кнопки**. Figma-title удали. Не храни его как фальшивый alt. Для самостоятельной содержательной фигуры (`<img>` схемы) пиши настоящий `alt` у картинки; не надейся, что имя Frame из Figma — предложение.

**`<desc>`** в экспорте Figma редок и полезен, только если его написал человек. Сгенерированный мусор уходит вместе с `<title>`.

**`<style>` с `.st0 { fill: #1E1E1E }`.** В `<img>` безобидно. Когда два inline SVG делят `.st0` — враждебно. Лучше presentation-атрибуты на элементах или один `currentColor` / CSS-переменная на path. Если таблица стилей нужна — скоупь её, а SVG без уникальных префиксов классов это делает плохо. Префикс дольше, чем удалить `.st0`.

**Presentation-атрибуты против CSS.** `fill="#1E1E1E"` на path легко грепать. `style="fill:#1E1E1E"` чуть хуже. Класс плюс `<style>` — худшее для инлайна. Инспекция — grep по всем трём.

**`fill="#1E1E1E"` на каждом path.** На белом превью «как в макете», в тёмной теме — нет. Это продуктовое решение в том же экспорте, что и `Layer_1`. UI-глифы отдают цвет компоненту (`currentColor` или `fill="currentColor"` / `stroke="currentColor"`). Фирменные знаки — нет. Не переписывай логотип слепым поиском. Не пропускай перепись у нав-иконки 24px, потому что «в светлой канве Figma всё верно».

Начальный `fill` в SVG — **чёрный**, не none. Presentation-атрибуты — специфичность 0: страничный `.st0` бьёт `fill="#1E1E1E"` на элементе. `currentColor` — used value свойства `color`. Корневой `fill="none"` у линейных иконок несущий; SVGO `removeUnknownsAndDefaults` как «лишнее» заливает шеврон. Смотри после SVGO.

`<img>` всё равно клипует Frame `clipPath` внутри своего документа. Изоляция не заменяет снятие лишнего клипа фрейма.

## Обводки: экспортёр — не канва

Модель stroke в Figma богаче, чем в SVG. Экспортёр аппроксимирует. Когда аппроксимация врёт, файл в Figma «почти тот», в браузере другой — а path на месте.

**Выравнивание.** Figma: center / inside / outside. SVG 1.1 — только center (`stroke-alignment` не интероп). Inside/outside обычно **outline в залитый path**; оставшийся center съезжает по весу. Inside вровень с 24 потом overflow или тонкий вид. Один набор: все outlined или все center плюс inset.

**Scale stroke** (ромб Figma): визуальная толщина постоянна при ресайзе канвы. SVG stroke растёт с CTM `viewBox` → viewport. `vector-effect="non-scaling-stroke"` — user-space; на 16/24/32 не ставь. Outline или принять масштаб.

**Кэпы/join** уезжают в экспорт. Шип miter — `stroke-miterlimit` (дефолт SVG 4). Острый угол может вылезти за viewBox — overflow, не пропавший `d`. Для UI — round.

**Пунктир** (`stroke-dasharray`) в user units; ритм 16 ≠ 24. Для UI-точек — кружки.

**Открытый path + `fill` не `none`:** SVG заливает хорду. Figma могла показать stroke-only. Grep `fill` на каждом path, не только на корне.

## Векторные сети, булевы и fill-rule

Инструмент вектора в Figma — это **сеть** (у вершины больше двух рёбер). SVG-path — нет. Экспорт обходит сеть в один или несколько `d`. «Одна» форма в Figma может стать тремя path или составным path с дыркой.

Булевы операции:

- **Union** должен стать одним силуэтом. Если нет — flatten до экспорта.  
- **Subtract** становится дыркой. В SVG это либо составной path (`d` с двумя субпутями) и `fill-rule="evenodd"`, либо `nonzero` с противоположным обходом. Обход неверный — дырка заливается.  
- **Intersect / exclude** — обычный источник лишних path и сюрпризов evenodd.

Дефолт `fill-rule` — **`nonzero`**. `evenodd` на треугольнике — булевый мусор. `evenodd` оставляй для настоящей дырки (составной `d` с двумя субпутями). `mergePaths` склеивает `d` — это не CSG-union; неверное правило дырявит или заливает. Перекрытия без булевой рисуются дважды; `opacity="0.5"` это выдаёт.

## Текст, шрифты и reflow, который выглядит как клип

Если в экспорте остался `<text>`, браузер возьмёт шрифт. Figma использовала Inter / SF / кастомный файл. Браузер — что установлено или загружено. Метрики другие. Буквы клипуются о Frame `clipPath`, переносятся или вылезают. Это не баг `viewBox`.

Для **иконок** outline текста в Figma до экспорта («Outline stroke» — не та команда; нужен flatten / outline текстового объекта в path). Для **вордмарков** либо outline (неизменяемо, живого текста нет), либо везти шрифт вместе с SVG и принять reflow — тулбару это почти никогда не нужно.

`<tspan>` с абсолютными `x`/`y` — Figma раскладывает строки. Нормально, пока кто-то не удалит `clipPath` и спрятанная вылезшая строка не станет видимой. Читай текстовые ноды.

Нет `xmlns="http://www.w3.org/2000/svg"` у фрагмента, который вставили в HTML, обычно нормально (HTML SVG integration). Тот же фрагмент как файл `.svg` может не нарисоваться. В инспекцию входит вопрос: это файл или сниппет?

## Фильтры, blend mode и фальшивый вектор

Если файл тяжёлый для иконки 24, ищи `filter`, `feGaussianBlur`, `feOffset`, `feColorMatrix`, `feBlend`, `style="mix-blend-mode`, `<image`.

Тени в Figma становятся графом фильтра, у которого **область фильтра** больше глифа (`x="-20%" width="140%"` и похожее). Нарисованное — и иногда выгруженный `viewBox` — раздувается под блюр. Иконка с полями или мыльная. На 16–24px в интерфейсе CSS `filter: drop-shadow(...)` на `<svg>` (или никакой тени) почти всегда лучше, чем везти `feOffset` + `feGaussianBlur`. Внутренние тени хуже: на малом размере растеризуются плохо.

**Layer blur** — фильтр. **Background blur** на канве — не настоящий SVG `feGaussianBlur` страницы за иконкой; Figma не упакует твой дашборд в SVG. Экспорт либо выкинет эффект, либо подменит полупрозрачной заливкой. Если мок держался на стекле, SVG этого не даст.

**Blend modes** (`multiply`, `overlay`) становятся `style="mix-blend-mode:…"` или `feBlend`. Они блендятся с тем, что за SVG в браузере, а это не канва Figma. Иконка, которая была верной на сером фрейме, будет неверной на белой кнопке. Для UI-глифов flatten блендов в Figma.

«Вроде SVG, рисуется как PNG»: `<image href="data:image/png;base64,…">` (или `xlink:href`) внутри `<svg>`. Это сплющенный битмап — растеризованный блюр, фотозаливка, импортированный PNG во фрейме или случайный скриншот. Никакая гигиена `viewBox` не сделает его чётким в 2×. Файл спокойно весит 80 КБ на одну иконку. Перерисуй вектором или честно выгрузи PNG и считай его растром.

`xlink:href` против `href`: SVG 2 предпочитает `href`. Браузеры ещё принимают `xlink:href` с неймспейсом. Снесёшь `xmlns:xlink` и оставишь `xlink:href` — картинка умрёт. Либо оставь неймспейс, либо перепиши на `href`.

## Градиенты и заливки

Линейные и радиальные заливки Figma становятся `<linearGradient>` / `<radialGradient>` в `defs`, ссылка `fill="url(#paint0_linear_12_8)"`. Чеклист инспекции:

- id градиента столкнётся при инлайне — префикс.  
- Дефолт `gradientUnits` — **`objectBoundingBox`** (0–1 формы-ссылки). `userSpaceOnUse` делит user space глифа — оставшийся page `viewBox` сдвинет краску, когда сузишь коробку.  
- `gradientTransform` — матрица; flatten вместе с остальным.  
- `stroke="url(#…)"` умрёт, если перепишешь stroke на `currentColor` — для нава ок, для логотипа нет.

Image fill на форме становится `fill="url(#pattern…)"` или `<image>`. Снова фальшивый вектор.

## Что выкинуть, что оставить, что выгрузить заново

Полезная чистка скучная. Это не «минифицируй всё».

**Для UI-иконок выкинуть**

- Лишний `clipPath` / `mask`, которые дублируют Frame (Clip content).  
- Обёртки, чей единственный смысл — `translate` на страницу.  
- `id="Layer_1"`, редакторские `<title>` / `<desc>`, комментарии.  
- `width`/`height` на корне *когда* размер уже задаёт CSS или проп `size` (оставь, если файлу нужна intrinsic-величина как у `<img>` без CSS).  
- Поддеревья фильтров для теней, которые вы не повезёте.  
- `xmlns:xlink`, если никто не использует `xlink:href`.  
- Внутренний `<style>` с общими классами.  
- `version="1.1"` и неймспейсы редактора (`xmlns:figma`, хвосты Inkscape, если файл побывал в другом инструменте).  
- Двенадцать знаков после запятой в командах path. На 24 единицах хватает двух–трёх; больше раздувает диффы.

**Оставить**

- Честный `viewBox`.  
- Path (или упрощённый union).  
- `fill="none"` на корне, если иконка обводками.  
- Настоящие дырки (`evenodd` или составной path, который умеешь объяснить).  
- Уникальные id **только** если градиенты или клипы реально нужны.  
- `stroke-linecap` / `stroke-linejoin`, которые часть рисунка.

**Лучше выгрузить заново, чем править руками**, если:

- `viewBox` размером со страницу и пять вложенных групп.  
- Текст всё ещё `<text>`, а нужны контуры.  
- Обводки должны стать заливками для силуэта (outline stroke, потом union).  
- Inside/outside должны совпасть с канвой, и ты не хочешь держать матрицу аппроксимаций.  
- Выделили не тот Frame, Section или инстанс-на-странице.  
- В образе участвовали blend modes и background blur.

Сплющить один шеврон руками — нормально. Сплющить набор из 40 иконок — как следующий человек «починит» `translate` в CSS. Верни работу в Figma: icon Frame, Clip content выкл., flatten булевых, outline текста, экспорт компонента.

## SVGO: полезен, не разумен

SVGO хорошо сжимает числа, выкидывает неймспейсы редактора, дефолтные атрибуты и пустые группы. Он **плохо** понимает, что `clip0_12_8` был фреймом. Настрой так, чтобы **контракт** выжил. Не гоняй слепой пресет по файлу, на который не смотрел.

Плагины, которые регулярно портят экспорт иконок:

| Плагин / поведение | Что ломается |
| --- | --- |
| `removeViewBox` | `<img>` / background падают к 300×150. |
| `cleanupIds` без префикса, потом инлайн | Столкновения; пустые иконки. |
| `removeUselessDefs` до снятия ссылки на клип фрейма | Сирота против пропавшего клипа — важен порядок. |
| `mergePaths` | Не те дырки; мусор evenodd. |
| `convertShapeToPath` | Нормально, пока не хотел грепать `cx`/`r`; обычно ок. |
| `removeUnknownsAndDefaults` снимает `fill="none"` | Начальный fill — чёрный → залитые линейные иконки. |
| `convertPathData` (`floatPrecision`, `utilizeAbsolute`) | Углы сетки 24 съезжают с пикселя; «мягкая» иконка. |
| `removeHiddenElems` | Может снять `opacity="0"` отладочные слои — обычно ок — и снять overflow, который ещё был нужен. |
| Плагин, который переписывает `viewBox` из `getBBox()` **до** снятия page-`translate` | Кроп не той коробки; пустой превью. |

Плагин, который переписывает `viewBox` из `getBBox()`, полезен *после* снятия page-translate и *после* запаса под stroke. До этого он спокойно обрежет по clip-rect или по линии с высотой bbox 0.

Гоняй SVGO в CI по **уже почищенному** файлу, не вместо инспекции. Вали билд на:

- `data:image/png` в папках UI-иконок  
- `viewBox="0 0 1440` (или любой viewBox шире, скажем, 128) в этих папках  
- `translate(` с числами больше 32 у UI-иконок  
- сырые `clip0_` / `paint0_` id, если инлайните без префикса  
- `<text` в папках иконок  
- `Layer_1`

Эти grep грубые и очень рабочие. Они кодируют рецепт, чтобы инспекция не была героизмом.

## Один проход в прод: source, превью, потом CI

1. **Вставь сырой экспорт**, потом **дважды** на одну страницу. Вторая копия умерла — столкновение id или `.st0`.  
2. **Grep** `clip0_`, `paint0_`, `<style`, `<title`, `<text`, `filter`, `<image`.  
3. **Префиксируй или сними id**, пока не легла вторая иконка.  
4. **Смотри после SVGO**, не только до: `viewBox` и `fill="none"` выжили?  
5. **Остановись, когда две копии всё ещё глиф**, без общей таблицы стилей и без редакторского title.  
6. **Только тогда** размер в месте вызова и способ вставки.

Редактор на [getsvgeditor.com](https://getsvgeditor.com): source рядом с превью, ничего не уезжает. Вставь **дважды** — тест id. Вкладки React/PNG — после. SVGR делает `clip-path` → `clipPath`; конвертация клипа фрейма, который надо было удалить, даст пустой компонент. [SVG → React](https://getsvgeditor.com/svg-to-react) / [SVG → PNG](https://getsvgeditor.com/svg-to-png) нужен честный `viewBox`. Пусто как **один** файл → [граф сцены](https://getsvgeditor.com/blog/ru/figma-svg-empty-shifted-clipped), не `prefixIds`.

Размер: [viewBox vs CSS](https://getsvgeditor.com/blog/ru/svg-viewbox-vs-width-height-css). Вставка: [inline vs img vs sprite](https://getsvgeditor.com/blog/ru/inline-svg-vs-img-vs-background-vs-sprite).

## Аудит в прод (две копии на одной странице)

1. Вторая вставка умерла или перекрасила первую → id / `.st0`.  
2. `clip0_` / `paint0_` без префикса при инлайне.  
3. В дереве `<title>Layer` / `Frame 214`.  
4. `<style>` с общими классами.  
5. UI-глиф всё ещё `#1E1E1E` / `#111` (не логотип).  
6. `<text>`, которому нужен outline; `<image>` / `filter` на иконке 24.  
7. SVGO уже гоняли: `fill="none"` и `viewBox` на месте.  
8. `fill-rule="evenodd"` на форме без дырки.

Пусто/съезд **как один файл** — [статья про сцену](https://getsvgeditor.com/blog/ru/figma-svg-empty-shifted-clipped). Про `currentColor` не начинай, пока тот проход зелёный.

## Договоритесь о рецепте экспорта, а не о героической чистке

Инспекция не масштабируется, если каждая иконка — отдельная археология. Запишите рецепт один раз, чтобы «выглядит сломанным» означало одни и те же пять минут для всех.

| Шаг | Решение |
| --- | --- |
| **В Figma** | Отдельный **Frame компонента** 20 или 24, не страница. Clip content **выкл.**, если не нужен настоящий кроп. Boolean union до одного силуэта. Outline текста. Outline stroke только если системе нужны заливки — и тогда на весь набор. Center stroke с оптическим зазором или все outlined — не мешать. Экспорт основного компонента, не инстанса на моке. SVG в 1×; не используй 2× как трюк резкости. |
| **В файле** | Честный `viewBox`, без клипа фрейма, без page-`translate`, без `Layer_1`, без общих CSS-классов, префикс id только когда краски настоящие. |
| **В CI** | SVGO с сохранёнными `viewBox` и `fill="none"`; префикс id, если инлайните; падать на остатках `clip0_`, огромных viewBox, встроенном PNG, `<text` в папках иконок. |
| **В приложении** | Размер в месте вызова. Вставка по задаче. Цвет через `currentColor` для UI-глифов. Не компенсировать трансформы в CSS. |

Недоверенные загрузки — другой пайплайн: санитайз, превью как `<img>` или в песочнице, никогда сырую разметку в DOM. Инспекция экспорта Figma предполагает: файлу дизайнера доверяешь, *графу сцены* — нет. Если файл из интернета, в инспекцию входят `<script>`, обработчики событий и `foreignObject` — и это не вставляют в привилегированный DOM. У иконки дизайн-системы этих нод просто не должно быть.

Экспортёр всё равно привезёт столкновения id и аппроксимацию stroke. Считай «сломалось в React» как **две копии на одной странице**, не как баг JSX. Когда id уникальны и `fill="none"` жив, path почти всегда был в порядке.
